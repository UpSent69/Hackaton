# Checklist — склад сети ресторанов

Веб-приложение для кейса «Мониторинг остатков, сроков годности и стоп-листов». Оно ведёт склад трёх ресторанов одной сети:
- принимает поставки, в том числе из фото и документов через локальную нейросеть Qwen;
- следит за сроками годности каждой партии;
- само собирает стоп-лист;
- подсказывает горячие предложения;
- считает аналитику.

Сотрудники всех ресторанов общаются в общем чате.

## Возможности

| Раздел | Что делает |
|---|---|
| **Склад** | Остатки по продуктам и партиям. Столбики показывают остаток партии, цвет — срок годности. Просроченную партию списывают вручную |
| **Поставки** | Ручной ввод или импорт файла: фото, PDF, Word, Excel, CSV, TXT. Позиции распознаются Qwen и сопоставляются со складом по смыслу («помидоры свежие» → «Томаты»). Поставку поставщика рассматривает менеджер: принимает целиком, частично или отклоняет с причиной |
| **Заявка** | Заявка заказчика на банкет из блюд меню. Цена порции, скидки, проверка, хватит ли продуктов на все порции |
| **Меню** | Блюда, их состав на порцию и цена порции. Сколько порций можно приготовить из остатков |
| **Заказы** | Касса. При оформлении заказа продукты списываются с партий с самым ранним сроком (FEFO) |
| **Стоп-лист** | Блюда, которые нельзя приготовить, и почему. Блюда, которые скоро закончатся |
| **Горячее** | Блюда, которые стоит продвигать, чтобы израсходовать продукты до конца срока. Рассчитываются автоматически, их можно добавить вручную, скрыть или удалить |
| **Сроки** | Все партии по срокам годности, фильтры по статусу |
| **Аналитика** | Списания, дефициты, прогноз стоп-листа, закупки. Разбор от Qwen с сезонными советами по меню |
| **Демо** | Ускорение времени, генератор заказов, наполнение примером — чтобы за пару минут показать весь путь партии |
| **Чат сети** | Плавающая кнопка на всех страницах. Над сообщением ресторан автора, рядом буква должности |

## Роли

| Роль | Кто это | Что может |
|---|---|---|
| **Владелец** | Первые два зарегистрированных аккаунта | Входит в любой из трёх ресторанов с полными правами. Заводит директоров, сотрудников и поставщика |
| **Директор** | Один на ресторан | Полные права, но только в своём ресторане. Заводит менеджеров и официантов |
| **Менеджер** | Сотрудник ресторана | Видит данные ресторана, рассматривает поставки и горячие предложения официантов |
| **Официант** | Сотрудник ресторана | Оформляет заказы, предлагает горячие предложения на рассмотрение |
| **Поставщик** | Один на всю сеть | Отправляет поставки в выбранный ресторан, видит их статус |

У каждого ресторана свои склад, меню, заказы, заявки, уведомления и аналитика. Данные одного ресторана в другом не видны.

## Архитектура

```
Браузер → frontend (nginx, :80) → gateway (nginx) → core            ─┐
                                                  → notification-service ─┤  SQLite (общая база)
                                                                          │  Redis
               core ⇄ Kafka ⇄ ai-service ⇄ Ollama (Qwen на компьютере)   ─┘
                    ⇄ Kafka ⇄ notification-service
```

| Сервис | Назначение |
|---|---|
| `frontend` | Статические страницы на HTML, CSS и JS, проксирует `/api/` в шлюз |
| `gateway` | API-шлюз: `/api/alerts` отправляет в notification-service, остальное — в core |
| `core` | HTTP API сайта. Единственный сервис, который создаёт и обновляет схему базы |
| `ai-service` | Распознавание документов и аналитика Qwen. Задачи получает из Kafka |
| `notification-service` | Уведомления из событий склада и лента `GET /api/alerts` |
| `kafka` | Обмен между сервисами. Топики: `documents.parse` / `documents.results`, `analytics.requests` / `analytics.results`, `warehouse.events` |
| `redis` | Сессии, кэш ответов, ограничение частоты запросов, результаты распознавания |

Все Go-сервисы собираются из одного кода в папке `auth-service`, роль задаёт переменная `SERVICE` (`core`, `ai`, `notification`). Без Kafka сайт работает, но распознавание файлов и анализ Qwen отвечают «временно недоступен». Без Redis всё работает через SQLite и память процесса.

## Быстрый старт

Нужны **Docker Desktop** и **Ollama** с моделью `qwen3.5:2b`. Без Ollama работает всё, кроме распознавания документов и анализа Qwen.

1. Установите Ollama и скачайте модель:
   ```
   ollama pull qwen3.5:2b
   ```
2. Разрешите подключения к Ollama из Docker. В PowerShell на Windows:
   ```
   setx OLLAMA_HOST 0.0.0.0:11434
   ```
   После этого перезапустите Ollama. Подробности и проверка доступа — в [REQUESTS_AI.md](REQUESTS_AI.md).
3. Запустите проект из корня репозитория:
   ```
   docker compose up -d --build
   ```
4. Откройте http://localhost, нажмите «Зарегистрироваться» и создайте аккаунт владельца. Первые два аккаунта становятся владельцами, остальных заводят в разделе «Администрирование».
5. Выберите ресторан. Чтобы быстро увидеть данные, откройте «Демо» и нажмите «Заполнить примером».

После обновления кода с удалёнными сервисами выполните `docker compose up -d --build --remove-orphans`. База обновляется сама при запуске core.

## Настройки

Переменные можно задать в файле `.env` рядом с `docker-compose.yml`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JWT_SECRET` | ключ для локальной разработки | Секрет подписи сессий, не короче 32 символов. На сервере обязательно задайте свой |
| `OLLAMA_URL` | `http://host.docker.internal:11434` | Адрес Ollama для ai-service |
| `OLLAMA_MODEL` | `qwen3.5:2b` | Модель для распознавания и аналитики |
| `REDIS_ADDR` | `redis:6379` | Адрес Redis |
| `KAFKA_BROKERS` | `kafka:9092` | Брокеры Kafka через запятую |

Ollama можно запустить и в контейнере: `docker compose --profile container-ollama up -d`. Тогда задайте `OLLAMA_URL=http://ollama:11434`.

## Структура репозитория

```
auth-service/          Go: все сервисы бэкенда
  internal/cmd/        точка входа, выбор роли сервиса (SERVICE)
  internal/handlers/   маршруты API: склад, поставки, меню, заказы, заявки, аналитика, чат
  internal/database/   схема SQLite и миграции
  internal/events/     работа с Kafka
  internal/requestimport/  извлечение текста из файлов, запросы к Qwen, сопоставление названий
frontend/              страницы сайта, nginx.conf
gateway/               конфигурация API-шлюза
backend-contract/      API.md — описание всех маршрутов, contract.go — типы запросов и ответов
docker-compose.yml     запуск всех сервисов
REQUESTS_AI.md         импорт документов через ИИ и настройка Ollama
PLAN.md                план работы над кейсом
```

Полное описание API, ролей, правил расчёта и Kafka — в [backend-contract/API.md](backend-contract/API.md).

## Полезные команды

```
docker compose ps                         # состояние сервисов
docker compose logs -f core               # логи core (или ai-service, notification-service)
docker compose restart core               # перезапустить сервис
docker compose down                       # остановить всё, данные сохраняются
```

Резервная копия базы сохраняется в том же томе, рядом с `app.db`:
```
docker run --rm -v hackaton_db_data:/d alpine cp /d/app.db /d/app.db.backup
```

## Технологии

Go 1.26 и SQLite (`modernc.org/sqlite`), Redis 7, Apache Kafka 3.8 (KRaft), nginx, Ollama с моделью Qwen 3.5 2B. Фронтенд написан на чистом HTML, CSS и JavaScript без сборки.
