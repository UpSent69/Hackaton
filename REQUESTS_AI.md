# Модуль «Заявка» — импорт с помощью ИИ

Модуль добавляет в Stoplist отдельную вкладку «Заявка». Пользователь загружает документ, получает редактируемую таблицу, сопоставляет строки со справочником товаров, проверяет цену, задаёт скидки и сохраняет заявку в SQLite. Существующий складской остаток этот этап не меняет.

## Форматы в этой версии

Поддерживаются TXT, CSV, TSV, JSON, XML, Markdown, LOG, XLSX, DOCX, PDF с текстовым слоем, PNG и JPG/JPEG. Размер файла — до 12 МБ.

Сканированные PDF пока не проходят OCR: загрузчик сообщает, что текст не найден. Для таких документов можно загрузить страницы как изображения PNG/JPG. Старый бинарный формат Excel XLS, старый Word DOC и другие расширения пока не поддерживаются.

Парсеры извлекают содержимое документа без сохранения исходного файла на сервере. SHA-256 исходного файла хранится с сохранённой заявкой, чтобы не сохранить один и тот же файл дважды.

## Как устроен модуль

- **frontend/requests.html** — отдельная страница вкладки.
- **frontend/requests.css** — стили редактора, таблицы, скидок и истории.
- **frontend/requests.js** — интерфейс загрузки, сопоставление строк, расчёт предпросмотра и работа с API.
- **auth-service/internal/requestimport/parser.go** — извлечение текста из поддерживаемых форматов, локальный вызов Ollama и запасной разбор таблиц.
- **auth-service/internal/handlers/requests.go** — API обработки, чтения каталога, изменения цен и сохранения заявок.
- **customer_requests** и **customer_request_items** — новые таблицы SQLite.
- **products.base_price_kopecks** — дополнительное поле цены каталога. Для старых БД колонка добавляется миграцией при запуске; старые записи остаются без цены.

Цена каталога хранится целым числом копеек. Модель никогда не придумывает цену: если базовая цена настроена, сервер читает её из БД и она имеет приоритет над значениями браузера. Если у существующего в каталоге товара цена в БД не задана, администратор может указать разовую цену непосредственно в строке заявки. Она сохраняется в снимке только этой заявки и не меняет каталог. Базовые цены по-прежнему можно менять в блоке «Цены каталога». Общая скидка применяется после скидки конкретной позиции; итог рассчитывается с округлением до копейки.

Для товаров выводится доступный остаток по неистёкшим партиям. Если товар не найден в каталоге, интерфейс сразу сообщает, что его нет в каталоге/на складе; для сохранения нужно добавить товар через «Поставки» или выбрать существующую позицию. Если товар найден, но доступный остаток нулевой, это также явно показывается.

Простые TXT/CSV/TSV/MD/LOG-списки с распознаваемыми строками обрабатываются детерминированно без вызова Ollama — например, «шашлык 500 грамм». Для сложных документов используется локальная модель; объём текста ограничен 12 000 символами, время запроса к модели — примерно 24 секунды. Если модель не распознала позиции или не ответила, выполняется упрощённый разбор и в интерфейсе появляется предупреждение.

При сохранении Go повторно читает цены из БД и сам рассчитывает итог. Значения итогов, присланные браузером, не принимаются за истину. Не сопоставленные товары, неуказанные цены, несовместимые единицы измерения и неправильные количества блокируют сохранение. Заявка и её позиции записываются одной транзакцией.

## Подключение бесплатной локальной модели

Рекомендуемая начальная конфигурация — Ollama и Qwen 3.5 2B. Модель запускается на твоём ПК/сервере, поэтому платный API не нужен и содержимое заявки не требуется отправлять стороннему облачному провайдеру. После скачивания модели для её работы интернет не нужен.

1. Установи Ollama для Windows с официального сайта: https://ollama.com/download
2. В PowerShell выполни:

~~~~powershell
ollama pull qwen3.5:2b
ollama run qwen3.5:2b
~~~~

После проверки можно выйти из интерактивного режима модели. API Ollama по умолчанию работает на порту 11434 и слушает только loopback-адрес. Чтобы backend в Docker мог обратиться к Ollama на Windows, в PowerShell выполни:

~~~~powershell
[Environment]::SetEnvironmentVariable("OLLAMA_HOST", "0.0.0.0:11434", "User")
~~~~

Затем полностью заверши Ollama через значок в системном трее (Quit/Выход) и снова запусти из меню «Пуск». Настройка `OLLAMA_HOST` меняет адрес прослушивания; проверь, что брандмауэр Windows не разрешает доступ к порту 11434 из недоверенных сетей. Не настраивай проброс порта на роутере и не открывай Ollama в интернет. Это нужно только для доступа из локального Docker.

3. В корне проекта создай файл .env:

~~~~dotenv
OLLAMA_URL=http://host.docker.internal:11434
OLLAMA_MODEL=qwen3.5:2b
JWT_SECRET=replace-this-with-a-random-secret-at-least-32-characters
~~~~

4. Перезапусти приложение:

~~~~powershell
docker compose up --build -d
~~~~

В docker-compose.yml ai-service (он распознаёт файлы и считает аналитику) по умолчанию использует Windows Ollama по адресу `http://host.docker.internal:11434`. Переменные OLLAMA_URL и OLLAMA_MODEL можно переопределить в .env. Для проверки сначала выполни `Invoke-RestMethod http://localhost:11434/api/tags` на Windows, затем проверь доступ из контейнера:

~~~~powershell
docker compose exec ai-service sh -c 'echo "$OLLAMA_URL $OLLAMA_MODEL"; wget -qO- "$OLLAMA_URL/api/tags"'
~~~~

Ответ со списком моделей должен содержать `qwen3.5:2b`. Если команда в контейнере не проходит, проверь `OLLAMA_HOST` и правила брандмауэра Windows. Альтернативный, отдельный Ollama-контейнер включается явно через `docker compose --profile container-ollama up -d`; в этом случае модель потребуется отдельно скачать внутри него.

Локальные модели используют память и CPU/GPU. На ПК с 16 ГБ RAM и GTX 1060 3 ГБ модель 2B — самый осторожный старт, но обработка может быть медленной. Если Ollama не отвечает, модуль не падает: он пытается разобрать табличный текст упрощённым способом и помечает черновик как требующий ручной проверки.

Официальная карточка модели: https://ollama.com/library/qwen3.5:2b

## API

Все маршруты требуют действующую сессию Bearer:

- POST /api/requests/parse — multipart/form-data с полем file; только анализ, без записи заявки.
- GET /api/requests — последние 100 сохранённых заявок с позициями.
- GET /api/requests/{id} — одна сохранённая заявка.
- POST /api/requests — сохранение отредактированного черновика; только администратор.
- POST /api/products/{productId}/price — задать базовую цену в копейках; только администратор.

JSON для сохранения:

~~~~json
{
  "customerName": "ООО Пример",
  "sourceFilename": "request.xlsx",
  "sourceHash": "пустая строка для заявки без файла",
  "globalDiscountPercent": 5,
  "items": [
    {
      "productId": "1",
      "quantity": 3,
      "itemDiscountPercent": 10,
      "unitPriceKopecks": 2500
    }
  ]
}
~~~~

Поле unitPriceKopecks необязательное и передаётся только для строки, у которой цена в каталоге не задана; это ручная цена конкретной заявки в копейках. Если цена в БД есть, сервер проигнорирует присланное значение и возьмёт цену из каталога. sourceHash может быть пустым только для заявки, созданной вручную без исходного файла.

## Что эта версия не делает

Это модуль подготовки и хранения заявки, а не полноценная ERP: после сохранения нет автоматического списания/прихода товаров, выставления счёта, отправки на согласование или интеграции с внешним документооборотом. Автоматическое проведение и OCR сканов можно добавлять отдельно после проверки качества на реальных документах.
